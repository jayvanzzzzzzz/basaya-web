# BaSaya Final Defense: Website and Android App Presentation Flow

**Language:** English  
**Suggested duration:** 18 minutes of presentation, with 2 minutes of transition buffer  
**Panel questions:** Separate from the demonstration time  
**Prepared:** November 14, 2026

## 1. The story to follow

Present one learning cycle using the same class, lesson, and student throughout:

**Introduce the problem -> Admin prepares content -> Teacher assigns the lesson -> Student learns and submits work -> Teacher reviews results -> Explain benefits and limitations.**

This order gives the panel a reason for every screen you open. Explain each feature through three points: what the user needs, what the user does, and what result appears.

Use the Android app for the main student demonstration. Later, open the student website briefly to explain the alternative access option. Avoid repeating the entire lesson on both platforms.

The lesson order in this guide is your presentation sequence. It does not mean every lesson part is locked behind the previous one. In assessment mode, completing the lecture is the quiz prerequisite; authored lessons may omit the game or activity.

## 6. Admin website: show content preparation

**Time:** 2 minutes  
**Show:** Teacher management briefly, then the lesson library and one prepared lesson in the editor.

**Demonstration steps:**

1. Open the admin portal using the demonstration admin account.
2. Identify teacher management without creating a full account live.
3. Open the lesson library and select the prepared demo lesson.
4. Show the lesson title, description, and difficulty.
5. Point out the lecture, game, word-recognition activity, pronunciation/reading content, and quiz sections.
6. Play a few seconds of one saved model recording.
7. Show where the lesson is saved or published. Use the prepared version for the remaining demonstration.

**Suggested script:**

> The admin website provides a central place to manage teacher accounts and prepare the lesson library. Here, the admin organizes the content that teachers can assign to their classes.
>
> This sample lesson includes text and model audio, a vocabulary game, a word-recognition activity, reading practice, and a comprehension quiz. Model recordings are prepared and stored for reuse, so student playback normally uses an existing recording.

**Evidence to point out:** The prepared content is available in the lesson library and contains the parts you will demonstrate on the phone.

**Transition:**

> Once the lesson is available, the teacher decides which class will receive it and when students can access it.

## 7. Teacher website: show class access and assignment

**Time:** 2 minutes  
**Show:** Demo class, membership request, and lesson assignment.

**Demonstration steps:**

1. Switch to the teacher website and open the prepared class.
2. Show the class code and explain that students use it to request membership.
3. Open student join requests and approve the prepared request.
4. Point out that the approved student now appears in the class roster.
5. Open Add lesson, select the demo lesson, and show the schedule controls.
6. Explain assessment and practice modes. Use assessment for the main demonstration.
7. Save the assignment, or open the prepared assignment if it already exists.
8. Switch to the phone and show the lesson in the student's class.

If you demonstrate a new request live, use this short sequence: student enters code -> request becomes pending -> teacher approves -> student sees the class. Do not approve a prepared request and then submit the same request again.

**Suggested script:**

> Teachers manage their own classes. A student enters the class code to request membership, and the teacher approves the request before the student joins the class.
>
> The teacher then selects a lesson from the library and sets its availability. Assessment mode records official progress and results. Practice mode allows repeated learning without adding official scores or completion records to reports.

**Transition:**

> The assigned lesson is now available to the student. We will continue the demonstration in the Android application.

## 8. Android app: demonstrate the learning experience

**Time:** 6 minutes total  
**Show:** One student's assigned lesson.

Briefly identify sign-in and registration, then continue with the prepared session. Avoid spending the main demonstration typing account details.

### A. Home and lesson path — 30 seconds

**Do:** Show Mga Aralin, open the assigned lesson, and identify its available parts.

**Say:**

> The home screen shows lessons assigned to the student's class. Opening a lesson displays its learning activities and completion status. We will follow the order shown here for a clear demonstration.

### B. Lektura: reading and listening — 45 seconds

**Do:** Open the lecture, play a short model recording, show read-along highlighting when available, and finish the short lecture.

**Say:**

> Lektura presents the lesson through text and model audio. Students can listen while following the text. Lecture completion is tracked separately from scored performance, and completing the lecture unlocks the assessment quiz.

### C. Laro: vocabulary game — 45 seconds

**Do:** Open the crossword, connect letters to form a valid word, and point out how the word fills the grid.

**Say:**

> Laro supports vocabulary practice through a crossword activity. Students form the expected words using the available letters and receive immediate feedback.

Use a short prepared level. If the full game is longer, demonstrate one word and explain the remaining steps without claiming that the whole activity is complete.

### D. Gawain: word recognition — 45 seconds

**Do:** Open Gawain, read the instruction, select the requested word or words, and show the feedback.

**Say:**

> Gawain asks students to recognize the correct words within the lesson content. The system checks the response and provides feedback, while assessment results contribute to word-recognition monitoring.

### E. Bigkas: preparation and recorded reading — 2 minutes

**Do:**

1. Open the prepared page-based Bigkas lesson.
2. Play a model word, then hold the microphone control and pronounce the preparation word.
3. Show the accepted response and move through the short preparation list.
4. Display the reading sentence and play its model audio.
5. Hold the microphone to record the sentence, then release it to stop.
6. Play the preview. Point out the option to record again.
7. Submit the completed recording pages while online.
8. Show the awaiting-review state.

**Say:**

> Bigkas begins with preparation words. Speech recognition checks whether the expected word was recognized before the student continues. This preparation is ungraded and allows retries.
>
> The student then listens to the model sentence, records a reading, and previews the recording before submission. For this page-based activity, the teacher evaluates the submitted reading using a rubric. The submission remains awaiting review until a teacher saves the grade.

This describes page-based Bigkas. Older word-only lessons use a different pronunciation activity. Rehearse with the page-based lesson used in this guide.

### F. Pagsusulit and Progreso — 1 minute 15 seconds

**Do:** Open the unlocked quiz, answer the short prepared set or demonstrate a representative question, then show Progreso.

**Say:**

> Pagsusulit checks comprehension of the lesson. Progreso then organizes the student's learning information by area, including lecture completion, vocabulary, word recognition, pronunciation, and comprehension.
>
> Lecture completion indicates participation in the reading material. Scored results represent performance in the relevant activities. A newly submitted reading has no numerical pronunciation grade until the teacher reviews it.

If the sample quiz is too long to finish live, show its interaction and then open a clearly identified sample result. Keep the fresh attempt and the prepared result distinct.

**Transition:**

> We have shown what the student does. We will now return to the teacher website to show how the submitted work supports follow-up.

## 9. Teacher website: review readings and interpret reports

**Demonstration steps:**

3. Play a short section of the student's recording.
4. Show the three rubric criteria: Accuracy, Smoothness and pace, and Expression and phrasing.
5. Select scores from 1 to 4 and save the grade.
6. Open student progress and identify the relevant result.
7. Open the class report and show the skill summaries and item analysis.
8. Point out the available print/PDF and Excel reporting options without completing a lengthy export process.

**Suggested script:**

> The teacher can listen to the submitted reading and evaluate accuracy, smoothness and pace, and expression and phrasing. Each criterion uses a score from one to four. Saving the grade provides the recorded-reading result used for pronunciation monitoring.
>
> Individual progress shows where a student may need support. The class report provides a broader view, while item analysis highlights commonly missed questions or recorded difficult words when those data are available. This information can guide review activities and instructional follow-up.

Do not present skill summaries as one combined student grade. The system keeps student learning areas separate. A class-level summary, where displayed, has a different purpose.

**Transition:**

> In addition to the main lesson cycle, BaSaya includes tools that support access, communication, and independent word lookup.

## 13. Likely panel questions and suggested answers

### Why provide both a website and an Android app?

The website supports administration, classroom management, and student access through a browser. The Android app provides a native student experience with device recording, notifications, and downloaded content. Both use shared accounts and accepted learning records.

### What is the difference between the admin and teacher roles?

The admin manages shared resources such as teacher accounts and the lesson library. Teachers manage their own classes, student membership, assignments, reading reviews, and reports. Role checks and access rules restrict protected operations.

### Can a student join a class using only its code?

The code starts a membership request. Teacher approval is required before the student becomes an enrolled class member.

### Does the system automatically grade reading fluency?

For page-based Bigkas, speech recognition checks the preparation words. The student records the reading, and the teacher grades the submitted recording using Accuracy, Smoothness and pace, and Expression and phrasing. Preparation-word acceptance is separate from the teacher's reading grade.

### What does the speech recognition service do?

It converts recorded speech into recognized text. BaSaya compares that text with the expected preparation word. The reviewed configuration uses Whisper through Cloudflare Workers AI. Recognition may be affected by noise, pronunciation variation, and recording quality.

### How is the page-based reading grade computed?

The teacher selects 1-4 for each of the three criteria. The rubric score is their sum out of 12, converted to a percentage for the relevant skill record. For example, 3 + 3 + 4 gives 10/12, approximately 83.3%, before display rounding. A pending submission has no numerical grade.

### How are progress and scores different?

Completion shows whether required lesson parts have been finished. Skill results describe performance in specific learning areas. Lecture completion has no accuracy score. Other activities use their respective scoring rules, and page-based pronunciation uses the teacher's rubric result.

### How are results combined across lessons?

The system summarizes each skill separately using item weighting and a recency factor of 0.85, so newer evidence receives more weight. It does not combine all student skills into one overall student grade. Remarks require enough evidence: at least two lessons or ten items for the skill.

### What happens if a student keeps practicing?

Practice assignments allow repetition without saving official scores or completion records into assessment reports. Assessment assignments follow the official result and completion rules. Repeating practice does not replace an official assessment result.

### What works offline?

Previously downloaded lessons and audio support selected offline activities. Online speech checking and final reading submission still require a connection. Accepted cloud results depend on synchronization, permissions, and deadlines. For the student website, download controls are available in the installed PWA.

### What if offline work is uploaded after the deadline?

The server enforces deadlines and can reject late uploads, even if the student worked offline beforehand. Students need to reconnect before the deadline and confirm synchronization.

### What happens to a submitted reading while it awaits grading?

A successfully submitted reading completes the student's pronunciation submission step. It remains awaiting teacher review and is excluded from numerical skill averages until graded. Teacher review can remain available after the lesson closes.

### What does the item analysis tell the teacher?

It summarizes frequently missed quiz questions and recorded difficult pronunciation words where the required data exist. Items missed by at least half of the counted students are flagged for reteaching. It supports instructional decisions; it is not a diagnosis of a learning condition.

### Can students change their own scores or access another student's recordings?

Protected operations use authenticated identity, membership checks, and database or API authorization. Reading playback and grading require the appropriate owner or class teacher permissions. Explain the relevant controls without promising that every possible attack has been eliminated.

### Is the AI assistant a model your team trained?

No. It uses an existing model through Groq, with supplied BaSaya help content and instructions. It generates app-use guidance; the team did not train or fine-tune its underlying model. The reviewed default is openai/gpt-oss-20b, which deployment settings can override.

### How is the assistant different from class chat?

Class chat connects real members of the class. The web assistant generates guidance about using BaSaya. It cannot access personal records or perform account actions on the student's behalf, and it is instructed not to provide exercise answers or scores.

### How do you know BaSaya improves learning?

Answer with your actual study design, participants, instruments, and findings. Feature completion or a successful demonstration alone does not establish improved learning outcomes. If your evaluation measures usability or functionality, describe those results using that scope.

### What could be improved next?

Choose improvements supported by your actual findings, such as broader classroom evaluation, expanded teacher-reviewed content, speech performance in noisy environments, or additional accessibility testing. Clearly identify these as proposed work.

## 15. If the demonstration is interrupted

| Situation | Action | Suggested wording |
|---|---|---|
| Speech is not recognized | Check the microphone and make one clear retry; then use the prepared recording if necessary. | “Speech checking depends on the recording conditions. We will use our prepared example to continue the workflow.” |
| The connection fails | Switch to the downloaded lecture or backup demonstration video. | “This operation needs connectivity. Here is the recorded demonstration of the same process.” |
| A reading is still uploading | Check its actual status and use the prepared submitted reading for teacher review. | “The live recording is still pending upload. This previously submitted sample shows the review stage.” |
| A report shows insufficient data | Explain the threshold and open the labeled sample report. | “This new account has limited evidence. We prepared a sample dataset to demonstrate the reporting view.” |
| The current assessment cannot be repeated | Use a fresh prepared assessment or a practice entry for interaction. | “We will use the prepared sample for this demonstration because the official attempt has already been completed.” |
| A notification does not appear | Show the in-app notice and explain device permissions. | “Push display also depends on device permission and settings. The in-app notice is shown here.” |

Keep the explanation brief, identify prepared material honestly, and continue with the learning cycle.
